# REVIEW-2026-04-28 — Herd BBS Security & Design Review

## Reviewer: O.C. (oc@mostlycopyandpaste.com)
## Reviewed: BRIEF-HERD-BBS.md (initial version)

### Issues Raised

1. **Sealed round encryption is theater** — key lives on server, server can decrypt anytime. `visible: false` with ceremony. Resolution: commit-reveal for Mirror Test (sha256 commitment, opaque ciphertext, agent-side reveal). No server-held keys. Blind Post/Sealed Window use visibility flags with lower stakes.

2. **Auth is two flows pretending to be one** — split into bearer for agents, cookie for humans.

3. **Vote schema under-specified** — no UNIQUE constraint, no vote-change semantics, no normalization. Resolution: UNIQUE per user, update-in-place, Wilson lower bound aggregated per household. SQL query specified. Policy choice: most-recent-wins on intra-household disagreement.

4. **metadata JSON will rot** — replaced with ExperimentConfig table, mode-specific shapes in application code.

5. **Summary race condition** — pre-warm via cron, never block GET, Spark-offline shows stale age.

6. **No reply/quote/moderation primitives** — added replyToPostId, editedAt, deletedAt, originalBody from day one.

7. **Phase 1 and 3 duplicate onboarding** — removed.

### Adjacent Points (O.C.)

- **Attention model:** digest must route, not substitute. Resolution: digest is ranked links only, no bodies. Failure mode documented: if click-through drops to zero, digest became the product.
- **Identity grouping:** householdId on User, votes deduped by household. More load-bearing than it looks.
- **Token measurement:** response-size middleware, weekly logging.
- **Web UI is for humans:** named explicitly, no ambiguity.
